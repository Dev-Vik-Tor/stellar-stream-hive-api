# Integration Guide

This page is for anyone building against Stellar Stream Hive programmatically
&mdash; a bot, a dashboard, a payroll tool, or your own frontend. There are two
ways in: the [indexer API](/docs/api/overview) (fast, simple, eventually
consistent within one poll interval) or the contracts directly (authoritative,
requires a Soroban RPC endpoint and more setup). Most integrations should
start with the API and only reach for direct contract calls when they need to
*write* (create/withdraw/cancel), since the API is read-only by design.

## Querying the API

A minimal typed client for the four read endpoints:

```typescript
interface StreamView {
  id: string;
  sender: string;
  recipient: string;
  token: string;
  total_amount: string;
  withdrawn: string;
  start_ledger: number;
  end_ledger: number;
  cliff_ledger: number;
  cancellable: boolean;
  status: "pending" | "active" | "completed" | "cancelled";
  created_at: number;
  streamed_amount: string;
  withdrawable_amount: string;
  progress_percent: number;
}

interface Stats {
  total_streams: number;
  active_streams: number;
  total_streamed: string;
  total_withdrawn: string;
}

class StreamHiveClient {
  constructor(private baseUrl: string) {}

  private async get<T>(path: string): Promise<T> {
    const res = await fetch(`${this.baseUrl}${path}`);
    if (!res.ok) {
      const body = await res.json().catch(() => ({}));
      throw new Error(`${res.status} ${body.error ?? "unknown_error"}: ${body.message ?? res.statusText}`);
    }
    return res.json() as Promise<T>;
  }

  listStreams(): Promise<StreamView[]> {
    return this.get("/streams");
  }

  getStream(id: string): Promise<StreamView> {
    return this.get(`/streams/${encodeURIComponent(id)}`);
  }

  getStreamsBySender(address: string): Promise<StreamView[]> {
    return this.get(`/senders/${encodeURIComponent(address)}`);
  }

  getStreamsByRecipient(address: string): Promise<StreamView[]> {
    return this.get(`/recipients/${encodeURIComponent(address)}`);
  }

  getStats(): Promise<Stats> {
    return this.get("/stats");
  }
}

const client = new StreamHiveClient("http://localhost:8080");
const myStreams = await client.getStreamsByRecipient("GABC...XYZ");
```

<CalloutBox variant="warning" title="Don't do arithmetic on these fields as numbers">
  Every amount field above is typed `string`, not `number`, on purpose --
  see [API Overview: response conventions](/docs/api/overview#response-conventions).
  `Number("30000000000")` loses precision above 2<sup>53</sup>; always parse
  with `BigInt` before doing any arithmetic, as in the next section.
</CalloutBox>

## Computing `streamed_amount` client-side

You don't have to trust the API's (or the contract's) computed
`streamed_amount` blindly -- it's a pure function of five values that are all
public: `total_amount`, `start_ledger`, `end_ledger`, `cliff_ledger`, and the
current ledger. Here is the exact formula from
[Streaming Math](/docs/concepts/streaming-math), in TypeScript using `BigInt`
to match the contract's `i128` semantics precisely:

```typescript
/**
 * Mirrors api/src/streaming_math.rs::streamed_amount exactly, including the
 * multiply-before-divide ordering and every edge case. All amount/ledger
 * inputs are BigInt to avoid precision loss -- see the "why multiply before
 * divide" section of the streaming-math docs for why order matters here.
 */
function streamedAmount(
  totalAmount: bigint,
  startLedger: bigint,
  endLedger: bigint,
  cliffLedger: bigint,
  currentLedger: bigint,
): bigint {
  if (currentLedger < cliffLedger) return 0n;
  if (currentLedger < startLedger) return 0n;
  if (endLedger <= startLedger) return totalAmount; // zero-duration stream

  const cappedLedger = currentLedger < endLedger ? currentLedger : endLedger;
  const elapsed = cappedLedger - startLedger;
  const totalDuration = endLedger - startLedger;

  return (totalAmount * elapsed) / totalDuration; // multiply BEFORE divide
}

function withdrawableAmount(streamed: bigint, withdrawn: bigint): bigint {
  const diff = streamed - withdrawn;
  return diff > 0n ? diff : 0n;
}

// Example: the 30-day, 3,000 XLM stream from the streaming-math docs, read
// at the 15-day mark (half elapsed):
const streamed = streamedAmount(
  30_000_000_000n, // total_amount
  1_000_000n,      // start_ledger
  1_518_400n,      // end_ledger
  1_000_000n,      // cliff_ledger (none)
  1_259_200n,      // current_ledger (15 days in)
);
console.log(streamed); // 15000000000n
```

You need the current ledger sequence to evaluate this yourself; fetch it from
Horizon directly (`GET {horizon}/` returns `history_latest_ledger`) or from
any Soroban RPC's `getLatestLedger` method -- the indexer API doesn't expose
its internally-tracked ledger as a standalone field today, only baked into the
`streamed_amount`/`withdrawable_amount` it returns per-stream.

## Direct contract interaction

For write operations (`create_stream`, `withdraw`, `cancel_stream`), or if you
want to read contract state without depending on this indexer at all, call the
contracts directly via Soroban RPC. Using the
[`@stellar/stellar-sdk`](https://www.npmjs.com/package/@stellar/stellar-sdk)
JavaScript SDK:

```typescript
import { Contract, rpc, TransactionBuilder, Networks, BASE_FEE } from "@stellar/stellar-sdk";

const server = new rpc.Server("https://soroban-testnet.stellar.org");
const streamContract = new Contract("<STREAM_CONTRACT_ID>");

// Read-only call: no signing, no fee, resolves immediately via simulation.
async function getStreamedAmount(streamId: bigint): Promise<bigint> {
  const account = await server.getAccount("<ANY_FUNDED_ACCOUNT_ADDRESS>");
  const tx = new TransactionBuilder(account, { fee: BASE_FEE, networkPassphrase: Networks.TESTNET })
    .addOperation(streamContract.call("streamed_amount", /* stream_id: */ nativeToScVal(streamId, { type: "u64" })))
    .setTimeout(30)
    .build();

  const sim = await server.simulateTransaction(tx);
  if (rpc.Api.isSimulationError(sim)) throw new Error(sim.error);
  return scValToNative(sim.result!.retval) as bigint;
}
```

For a state-changing call like `withdraw_max`, the same transaction must
additionally be signed by the recipient's key (via Freighter in a browser
context, or a `Keypair` server-side) and submitted with
`server.sendTransaction`, then polled with `server.getTransaction` until it
leaves the `PENDING` status -- see the
[Soroban RPC documentation](https://developers.stellar.org/docs/data/rpc)
for the full submit/poll lifecycle, which is generic to any Soroban contract
call and not specific to this platform.

### Write example: create a stream from the browser with Freighter

This end-to-end example builds a `create_stream` transaction, simulates it,
signs it with [Freighter](https://www.freighter.app/) through
`@stellar/freighter-api`, submits it, and polls until the result is final. It
runs in a browser page, because Freighter injects its signing API into the
page.

Versions: the code was type-checked against `@stellar/stellar-sdk` **17.2.1**
and `@stellar/freighter-api` **6.0.1**. It has not yet been run end-to-end
against testnet.

```bash
npm install @stellar/stellar-sdk@17.2.1 @stellar/freighter-api@6.0.1
```

<CalloutBox variant="warning" title="Placeholders">
  `<STREAM_CONTRACT_ID>` and `<XLM_SAC_CONTRACT_ID>` are placeholders. The
  contracts are not deployed yet -- see
  [Deployed contract addresses](#deployed-contract-addresses).
</CalloutBox>

```typescript
import {
  Address,
  BASE_FEE,
  Contract,
  Networks,
  nativeToScVal,
  rpc,
  scValToNative,
  TransactionBuilder,
} from "@stellar/stellar-sdk";
import {
  isConnected,
  requestAccess,
  signTransaction,
} from "@stellar/freighter-api";

const RPC_URL = "https://soroban-testnet.stellar.org";
const NETWORK_PASSPHRASE = Networks.TESTNET;
const STREAM_CONTRACT_ID = "<STREAM_CONTRACT_ID>";

const server = new rpc.Server(RPC_URL);

export interface CreateStreamParams {
  token: string;
  recipient: string;
  totalAmount: bigint;
  startLedger: number;
  endLedger: number;
  cliffLedger: number;
  cancellable: boolean;
}

/** Builds, simulates, signs with Freighter, submits and polls one create_stream call. */
export async function createStream(params: CreateStreamParams): Promise<bigint> {
  // 1. Make sure Freighter is installed and the user has granted this site access.
  const connected = await isConnected();
  if (connected.error || !connected.isConnected) {
    throw new Error("Freighter is not installed or not connected");
  }
  const access = await requestAccess();
  if (access.error) {
    throw new Error(`Freighter access was refused: ${access.error.message}`);
  }
  const sender = access.address;

  // 2. Build the transaction with the Stream contract's create_stream arguments.
  const account = await server.getAccount(sender);
  const stream = new Contract(STREAM_CONTRACT_ID);
  const unsigned = new TransactionBuilder(account, {
    fee: BASE_FEE,
    networkPassphrase: NETWORK_PASSPHRASE,
  })
    .addOperation(
      stream.call(
        "create_stream",
        new Address(sender).toScVal(),
        new Address(params.recipient).toScVal(),
        new Address(params.token).toScVal(),
        nativeToScVal(params.totalAmount, { type: "i128" }),
        nativeToScVal(params.startLedger, { type: "u32" }),
        nativeToScVal(params.endLedger, { type: "u32" }),
        nativeToScVal(params.cliffLedger, { type: "u32" }),
        nativeToScVal(params.cancellable, { type: "bool" }),
      ),
    )
    .setTimeout(30)
    .build();

  // 3. Simulate, and attach the resource footprint and fee the network asks for.
  const prepared = await server.prepareTransaction(unsigned);

  // 4. Sign in Freighter. The wallet checks that the signer matches `address`.
  const signed = await signTransaction(prepared.toXDR(), {
    networkPassphrase: NETWORK_PASSPHRASE,
    address: sender,
  });
  if (signed.error) {
    throw new Error(`Signing was rejected: ${signed.error.message}`);
  }
  const signedTx = TransactionBuilder.fromXDR(signed.signedTxXdr, NETWORK_PASSPHRASE);

  // 5. Submit and poll until the ledger that includes it closes.
  const sent = await server.sendTransaction(signedTx);
  if (sent.status === "ERROR") {
    throw new Error(`Submission rejected with status ${sent.status}`);
  }

  let result = await server.getTransaction(sent.hash);
  while (result.status === rpc.Api.GetTransactionStatus.NOT_FOUND) {
    await new Promise((resolve) => setTimeout(resolve, 1_000));
    result = await server.getTransaction(sent.hash);
  }
  if (result.status !== rpc.Api.GetTransactionStatus.SUCCESS) {
    throw new Error(`Transaction failed with status ${result.status}`);
  }

  // create_stream returns the new u64 stream id.
  return scValToNative(result.returnValue!) as bigint;
}
```

Call it with amounts as `bigint`, not `number`, and ledgers relative to the
current ledger from `server.getLatestLedger()`:

```typescript
const { sequence } = await server.getLatestLedger();

const streamId = await createStream({
  token: "<XLM_SAC_CONTRACT_ID>",
  recipient: "GABC...XYZ",
  totalAmount: 1_000_000_000n, // 100 XLM in stroops
  startLedger: sequence,
  endLedger: sequence + 720, // about one hour at ~5s per ledger
  cliffLedger: sequence, // no cliff; use sequence + 360 for a halfway cliff
  cancellable: true,
});
```

<CalloutBox variant="info" title="When to prefer direct contract calls over the API">
  Reach for direct RPC calls instead of the indexer API when you need: (1) a
  write operation, (2) absolute real-time reads with zero dependency on this
  API's 10-second poll interval, or (3) to verify the indexer itself is
  behaving correctly (compare its `/streams/:id` output against a direct
  `get_stream` + `streamed_amount` call). For everything else -- listing,
  filtering by sender/recipient, aggregate stats -- the API is simpler and
  doesn't require you to run or trust a Soroban RPC endpoint yourself.
</CalloutBox>
