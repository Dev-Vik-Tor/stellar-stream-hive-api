# Stream Contract

The Stream contract is the platform's main entry point: it owns each stream's
schedule, computes accrual using the formula in
[Streaming Math](/docs/concepts/streaming-math), and is the only contract
authorized to move funds in or out of the [Vault](/docs/contracts/vault). It
also pushes lifecycle updates to the [Registry](/docs/contracts/registry) so
platform-wide queries stay in sync.

Source: [`stellar-stream-hive-contract`](https://github.com/Stellar-Hive/stellar-stream-hive-contract)
(contract module `stream`). Deployment addresses are not yet published --
see [Getting Started](/docs/getting-started#deployed-contract-addresses).

## Types

### `Stream`

```rust
pub struct Stream {
    pub id: u64,
    pub sender: Address,
    pub recipient: Address,
    pub token: Address,
    pub total_amount: i128,
    pub withdrawn: i128,
    pub start_ledger: u32,
    pub end_ledger: u32,
    pub cliff_ledger: u32,
    pub cancellable: bool,
    pub status: StreamStatus,
    pub created_at: u64,
}
```

| Field | Type | Meaning |
|---|---|---|
| `id` | `u64` | Assigned by the Registry at creation time; stable for the life of the stream. |
| `sender` | `Address` | Funded the stream; may cancel it if `cancellable`. |
| `recipient` | `Address` | The only address that may withdraw. |
| `token` | `Address` | The Soroban token contract (e.g. the XLM SAC, or any SEP-41-compatible token) being streamed. |
| `total_amount` | `i128` | Total deposited, in the token's smallest unit. Immutable after creation. |
| `withdrawn` | `i128` | Running total already paid out to `recipient`. Only ever increases. |
| `start_ledger` | `u32` | Ledger sequence accrual begins at. |
| `end_ledger` | `u32` | Ledger sequence the stream is fully vested at. Must be `> start_ledger`. |
| `cliff_ledger` | `u32` | Ledger sequence before which nothing is withdrawable. `>= start_ledger`; equals `start_ledger` when there is no cliff. |
| `cancellable` | `bool` | Whether `sender` may call `cancel_stream`. Fixed at creation. |
| `status` | `StreamStatus` | Current lifecycle state -- see below. |
| `created_at` | `u64` | Unix timestamp the stream was created, for display purposes only (all accrual math uses ledger sequence, not this field). |

### `StreamStatus`

```rust
pub enum StreamStatus {
    Pending,
    Active,
    Completed,
    Cancelled,
}
```

- **`Pending`** -- created, but `start_ledger` has not been reached yet.
- **`Active`** -- between `start_ledger` and `end_ledger`; accrual is ongoing.
- **`Completed`** -- `end_ledger` has passed and the stream ran to full term.
- **`Cancelled`** -- the sender cancelled before `end_ledger` (see
  [Streaming Math: what happens on cancel](/docs/concepts/streaming-math#what-happens-on-cancel)).

`Pending` and `Active` are the only states `streamed_amount` treats as "still
accruing" for the purposes of the indexer's `is_active` check; `Completed` and
`Cancelled` are both terminal.

### `StreamError`

```rust
pub enum StreamError {
    AlreadyInitialized = 1,
    NotInitialized = 2,
    InvalidSchedule = 3,       // end_ledger <= start_ledger, or cliff_ledger < start_ledger
    InvalidAmount = 4,          // total_amount <= 0
    StreamNotFound = 5,
    NotRecipient = 6,
    NotSender = 7,
    NotCancellable = 8,
    AlreadyCancelled = 9,
    AlreadyCompleted = 10,
    NothingToWithdraw = 11,
}
```

## Functions

### `initialize`

```rust
pub fn initialize(env: Env, vault: Address, registry: Address)
```

One-time setup, called immediately after deployment. Stores the addresses of
the Vault and Registry contracts this Stream contract will call into.

- **Auth:** none enforced by convention beyond "must be called before any
  other function" -- deployment scripts should call this in the same
  transaction/batch as instantiation, before publicizing the contract address.
- **Errors:** `AlreadyInitialized` if called a second time.

### `create_stream`

```rust
pub fn create_stream(
    env: Env,
    sender: Address,
    recipient: Address,
    token: Address,
    total_amount: i128,
    start_ledger: u32,
    end_ledger: u32,
    cliff_ledger: u32,
    cancellable: bool,
) -> u64
```

Validates the schedule, calls `vault.deposit` to pull `total_amount` of
`token` from `sender` into the Vault, stores a new `Stream` in `Pending` (or
`Active`, if `start_ledger` has already passed) status, registers it with the
Registry, and returns the new stream's `id`.

- **Auth:** `sender.require_auth()`.
- **Returns:** the new `u64` stream id.
- **Errors:** `InvalidSchedule` if `end_ledger <= start_ledger` or
  `cliff_ledger < start_ledger`; `InvalidAmount` if `total_amount <= 0`.
- **Events:** emits `StreamCreated` (see [Events emitted](#events-emitted)).

```rust
let stream_id = client.create_stream(
    &sender,
    &recipient,
    &token_address,
    &30_000_000_000i128, // 3,000 XLM at 7 decimals
    &1_000_000u32,
    &1_518_400u32,       // 30 days later, at ~5s/ledger
    &1_000_000u32,       // no cliff
    &true,
);
```

### `streamed_amount`

```rust
pub fn streamed_amount(env: Env, stream_id: u64) -> i128
```

Returns how much of `total_amount` has vested as of the current ledger, using
the formula in [Streaming Math](/docs/concepts/streaming-math). Pure read;
does not consider the cliff (see `withdrawable_amount`, which does).

- **Auth:** none (read-only).
- **Errors:** `StreamNotFound`.

### `withdrawable_amount`

```rust
pub fn withdrawable_amount(env: Env, stream_id: u64) -> i128
```

Returns `streamed_amount - withdrawn`, or `0` if the current ledger is before
`cliff_ledger`.

- **Auth:** none (read-only).
- **Errors:** `StreamNotFound`.

### `withdraw`

```rust
pub fn withdraw(env: Env, stream_id: u64, amount: i128)
```

Withdraws exactly `amount` (which must be `<= withdrawable_amount`) to
`recipient`. Updates `withdrawn`, transitions `status` to `Completed` if this
withdrawal exhausts a stream that has reached `end_ledger`, and calls
`vault.release(stream_id, recipient, amount)`.

- **Auth:** `recipient.require_auth()`.
- **Errors:** `StreamNotFound`, `NotRecipient`, `NothingToWithdraw` (if
  `amount` exceeds `withdrawable_amount`), `AlreadyCancelled`.
- **Events:** emits `Withdrawn`.

### `withdraw_max`

```rust
pub fn withdraw_max(env: Env, stream_id: u64) -> i128
```

Convenience wrapper: withdraws the entire current `withdrawable_amount` in one
call and returns the amount withdrawn. Equivalent to reading
`withdrawable_amount` and passing it to `withdraw`, done atomically so there
is no race between the read and the withdrawal.

- **Auth:** `recipient.require_auth()`.
- **Returns:** the `i128` amount actually withdrawn (may be `0`, which is not
  an error -- it simply means nothing had accrued past the cliff yet).
- **Errors:** `StreamNotFound`, `NotRecipient`, `AlreadyCancelled`.
- **Events:** emits `Withdrawn` (unless the withdrawn amount is `0`).

### `cancel_stream`

```rust
pub fn cancel_stream(env: Env, stream_id: u64)
```

Cancels the stream if `cancellable` is `true` and it hasn't already completed
or been cancelled. Computes `streamed_amount` at the current ledger, calls
`vault.release` for any newly-withdrawable portion owed to `recipient` and
`vault.refund` for the remainder back to `sender`, and sets `status` to
`Cancelled`. See
[Streaming Math: what happens on cancel](/docs/concepts/streaming-math#what-happens-on-cancel)
for the exact split.

- **Auth:** `sender.require_auth()`.
- **Errors:** `StreamNotFound`, `NotSender`, `NotCancellable`,
  `AlreadyCancelled`, `AlreadyCompleted`.
- **Events:** emits `Cancelled`.

### `get_stream`

```rust
pub fn get_stream(env: Env, stream_id: u64) -> Stream
```

Returns the full stored `Stream` struct as-is (does not recompute accrual --
use `streamed_amount`/`withdrawable_amount` for live figures).

- **Auth:** none (read-only).
- **Errors:** `StreamNotFound`.

### `get_streams_by_sender` / `get_streams_by_recipient`

```rust
pub fn get_streams_by_sender(env: Env, sender: Address) -> Vec<u64>
pub fn get_streams_by_recipient(env: Env, recipient: Address) -> Vec<u64>
```

Returns the ids of every stream where the given address is the sender (or
recipient, respectively). Backed by an index maintained at `create_stream`
time; callers fetch full details per-id via `get_stream`.

- **Auth:** none (read-only).

### `get_status`

```rust
pub fn get_status(env: Env, stream_id: u64) -> StreamStatus
```

Returns just the `StreamStatus`, recomputing `Pending -> Active -> Completed`
transitions lazily based on the current ledger (so a stream whose
`end_ledger` has passed reports `Completed` even if no one has called
`withdraw` since then to persist that transition on-chain).

- **Auth:** none (read-only).
- **Errors:** `StreamNotFound`.

## Events emitted

These are the events `stellar-stream-hive-api`'s indexer
(`api/src/indexer/events.rs`) decodes from `result_meta_xdr`. See that module's
doc comment for the canonical reference; reproduced here for convenience:

| Event | Topics | Data |
|---|---|---|
| `StreamCreated` | `[Symbol("StreamCreated"), U64(id)]` | `Vec[Address(sender), Address(recipient), Address(token), I128(total_amount), U32(start_ledger), U32(end_ledger), U32(cliff_ledger), Bool(cancellable)]` |
| `Withdrawn` | `[Symbol("Withdrawn"), U64(id)]` | `I128(amount_withdrawn_this_call)` |
| `Cancelled` | `[Symbol("Cancelled"), U64(id)]` | `I128(sender_refund_amount)` |

## Security notes

- `withdraw` and `cancel_stream` both call into the Vault, but the Vault does
  not trust *this* contract's business logic to be correct out of blind
  faith -- it trusts a much narrower thing: that the caller is this specific
  contract address. See [Security Model](/docs/concepts/security-model) for
  why that distinction is the entire basis of fund safety here.
- `total_amount`, `cancellable`, `start_ledger`, and `end_ledger` are all
  immutable once a stream is created. There is no `update_schedule` function
  by design -- changing a schedule after funds are locked would reopen every
  security question this contract exists to close.
- All amount and ledger arithmetic uses `i128`/`u32` with checked operations
  (see [Streaming Math](/docs/concepts/streaming-math#why-multiply-before-divide));
  the contract never panics on attacker-supplied numeric input, it returns a
  typed `StreamError` instead.
